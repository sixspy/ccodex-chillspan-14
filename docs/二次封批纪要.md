# 二次封批纪要（定稿·当班封死）

- 定稿日期：2026-11-23
- 适用范围：同一批次已存在正式封批代后的任何再次封批请求
- 库路径：`data/app.db`（文件库），不改库结构、不改落库路径
- 结论：只走**甲路径**，不折中，不开乙路径。

## 一、唯一落库路径（甲路径）

同一批次只要已存在**正式封批代**（`seal_snapshots.status='已封批'` 的代）：

1. 二次封批**正式代零增**；
2. 请求**拒写**（HTTP 409），不得新增任何 `seal_snapshots` 行；
3. 不得出现影子代草案与正式代并列；
4. 每次拒写记审计 `二次封偏航`，记录既有正式代与本次企图代次。

乙路径（再封只增影子代草案、正式代计数零改、待去重规则晋升）本仓**不启用**。不许
甲乙混用；混用会出现双代正式并存，属明令禁止。

## 二、并发争用

两人同时对同一已封批次再点封批：

- 必须抢 `batch:{batch_id}` 批次锁；
- 后到者争用**仅记痕**（`contention_log`），不写业务、不增代；
- 争用痕须在拒写事务中落库，不得随异常回滚丢失。

## 三、五页同源

封批页、批次页、温谱页、血缘页、对账页的“代”一律取自同一解析源
`seal_state.official_generation`：有正式封批代取正式代（唯一），无则回退批次当前代。
禁止只在封批页改代次列表而其余页面各算各的。

## 四、验收口径

- 测试源文件：`tests/test_double_seal.py`，经 pytest 先见红再转绿；
- 甲：二次封批仍增正式代 → 红；
- 乙：影子代未晋升却与正式代并列 → 红；
- 争用：双人同批抢再封 → 红；
- 五页同源：五页正式代必须一致；
- 失败测未绿，不得回滚本禁令；禁止跳过争用测；禁止无测改接口；
- 收工复查封批、批次、温谱、血缘、对账五面，同批仅留一正式代。
